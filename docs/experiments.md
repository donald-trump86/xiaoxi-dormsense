# 课程实验设计与规范

本文是面向**无线传感网络**与**大数据基础**两门本科课程的**待执行实验方案**。
当前仓库处于工程初始化阶段，**不包含任何真实实验数据或伪造的实验结论**。
所有实验方案必须由六人小组成员在后续实际硬件就位、环境搭建完成后，依据本规范独立实施并记录真实数据。

## 1. 数据、计时与统计基准规范

### 1.1 数据分类与标记
所有参与实验的数据必须具有不可磨灭的真实性标记，严禁混淆：
- **真实采样 (`simulated=false`)**：来自物理 Arduino UNO R4 WiFi 节点及真实传感器引脚采集。必须详细记录传感器型号、引脚、供电、室内布点位置与采集时刻。
- **程序模拟 (`simulated=true`)**：由 `simulator/mqtt_node.py` 或测试脚本合成的数据。仅用于验证软件流转、去重逻辑与分析管线，不得作为硬件或通信性能结论。
- **人工构造 (`simulated=true`)**：手工编写的极端边界报文（如坏 JSON、错版本、越界值）。必须显式标记为测试用例，与采集流物理隔离。
- **历史回放 (`simulated=true`)**：重新灌入实时通信链路的历史切片。必须标记为回放流量，不得冒充实时现场采样。

### 1.2 节点身份、重启边界与去重键
- **去重主键**：统一使用三元组 `(node_id, boot_id, sequence)`。
- **重启切片**：每次微控制器启动或软复位，必须重新生成唯一的 `boot_id`。
- **序列连续性**：`sequence` 仅在单次 `boot_id` 生命周期内单调递增（0 开始）。重启后序号重置是合法行为，不可单用 `sequence` 跨重启去重，否则会导致严重误删。

### 1.3 时间戳与时钟基准约束
- **严禁虚构单向延迟**：由于微控制器节点通常缺乏高精度 RTC，且在校园 Wi-Fi 下尚未完成高精度 NTP 同步，**严禁用节点未同步的时间戳与服务器接收时间相减来宣称“单向网络传输延迟”**。
- **时间来源标准**：
  - 节点时间：未同步时必须为 `null`；仅在通过 NTP 成功授时后方可填写 RFC 3339 UTC 字符串（以 `Z` 结尾）。
  - 服务器接收时间：数据分析层与 Broker 接入层在收到报文的物理时刻，由宿主机打上单调纳秒时钟或受控的 UTC `received_at`。
- **时延测量口径**：在无精确时钟同步前提下，网络端到端时延仅允许通过同机测试探针注入与观测、或应用层回环 RTT（Round-Trip Time）进行测量。

### 1.4 样本集合、丢包率与成功率计算
丢包率与成功率必须明确观测时间窗口、观测点以及严格的集合分母，严禁只汇报空洞百分比：
- 设发送端在观测窗口 $W$ 内按采样策略生成的唯一样本集合为 $S$。
- 设接收端在等待合理到达宽限期 $T_{\text{grace}}$ 后收到的有效唯一样本集合为 $R$。
- **传输成功率**：$P_{\text{success}} = \frac{|S \cap R|}{|S|}$ （当 $|S| = 0$ 时标记为“不适用”）。
- **传输缺失率（丢包率）**：$P_{\text{loss}} = \frac{|S - R|}{|S|} = 1 - P_{\text{success}}$。
- 若发送端无持久化发送日志（仅靠接收端序列推断），分母定义为该启动段序号跨度：$N_{\text{span}} = \max(\text{seq}) - \min(\text{seq}) + 1$。此估算仅在单段连续采样且无首尾整段丢失时作为近似，且必须在报告中声明其局限性。

## 2. 无线传感网络课程实验方案 (WSN Experiments)

### 实验 1：MQTT 数据传输成功率测试
- **实验目的**：评估在不同网络负载与采样周期下，Arduino UNO R4 WiFi 节点向 Mosquitto Broker 发布 MQTT 遥测报文的端到端到达成功率。
- **实验方法**：
  1. 设定节点分别以 1s、5s、10s、30s 为采样周期，在恒定无线环境下连续发送 1000 个采样数据。
  2. 发送端本地串口记录每个采样序号 `sequence` 及哈希值，接收端订阅并落盘原始数据。
  3. 比较不同采样频率下的成功到达比例。
- **评价指标**：
  - 传输成功率 $P_{\text{success}} = |S \cap R| / |S|$。
  - 序号断裂分布直方图。

### 实验 2：传输延迟与往返响应时间 (RTT) 测试
- **实验目的**：测定应用层消息从发布到订阅端可见的耗时分布，以及命令-响应往返时延（RTT）。
- **实验方法**：
  1. **测试探针注入时延**：在同一物理宿主机上，由独立探针进程发布模拟报文并监听 HA 实体状态变更，计算从注入到可见的内部处理时延。
  2. **应用层 RTT 测量**：主机向节点 `command` Topic 发布带唯一 `command_id` 的状态翻转指令，节点收到后立即向 `status` 或 `event` Topic 返回执行确认；主机记录发送与收到的单调时钟差 $\Delta t$。
  3. 连续测试 100 次，排除首包连接建立开销后统计。
- **评价指标**：
  - 往返时延分布：中位数 $p50$、95分位数 $p95$、最大值 $p99$ 与平均值。
  - 超时率（超时阈值设定为 3000ms）。

### 实验 3：Wi-Fi RSSI 与通信表现关系实验
- **实验目的**：探究物理传播距离、障碍物及宿舍环境对 Wi-Fi 接收信号强度指示 (RSSI) 的影响，以及 RSSI 衰减对 MQTT 数据交付质量的作用规律。
- **实验方法**：
  1. 将 Arduino UNO R4 节点分别放置在宿舍不同位置（如：同一书桌、上下铺床头、关门后的走廊、宿舍阳台隔断处）。
  2. 节点通过 `WiFi.RSSI()` 获取当前连网信号强度，随遥测报文上报字段 `rssi`。
  3. 每个测试点连续采样 20 分钟（周期 10s），记录信号变化范围与接收丢包情况。
- **评价指标**：
  - 各测点 RSSI 均值与方差（单位：dBm）。
  - RSSI 与数据包到达成功率的点状散点图与相关系数。
  - 极弱信号（如 RSSI < -85 dBm）下的掉线率与重试次数。

### 实验 4：节点断线重连与 LWT（遗嘱消息）状态同步
- **实验目的**：验证当无线网络抖动、AP 临时关断或节点异常断电时，Broker 状态感知、遗嘱发布及节点指数退避重连机制的有效性。
- **实验方法**：
  1. 正常运行节点，人为切断测试 AP 电源或屏蔽射频信号 60 秒后恢复。
  2. 观察 Broker 是否在 KeepAlive (30s) 超时后正确触发 retained `offline` 遗嘱消息。
  3. 检查 HA 中传感器实体是否按预期置为 `unavailable`。
  4. 恢复网络后，观察节点是否按指数退避算法（如 1s, 2s, 4s... 60s）成功重建 TCP/MQTT 连接并重新发布 `online` 状态。
- **评价指标**：
  - 离线检测时延 $T_{\text{detect}}$（从实际断开到 HA 状态置为 offline 的时间）。
  - 网络恢复后的重连恢复时延 $T_{\text{recover}}$。
  - 重连过程中重发、覆盖与消息丢失统计。

### 实验 5：多节点并发通信与信道争用实验
- **实验目的**：测试当宿舍内存在多个传感节点（或模拟节点集群）同时向单个 Broker 发送遥测数据时，系统的并发处理能力与 Topic 隔离性。
- **实验方法**：
  1. 使用 1 个真实 UNO R4 节点与 $N$ 个并行模拟节点（如 $N = 2, 5, 10$）。
  2. 各节点独立按 5s 周期发送遥测，运行 30 分钟。
  3. 监控 Broker 的 CPU、内存消耗，检查是否存在跨节点 Topic 串扰或数据覆盖。
- **评价指标**：
  - 整体并发吞吐量（Message Per Second, MPS）。
  - 各独立节点 $node\_id$ 的到达成功率分布一致性。
  - 串扰率（收到 Topic 与 payload 不匹配的错误报文数，严格要求为 0）。

### 实验 6：数据丢失识别与恢复机制评估
- **实验目的**：量化微控制器在离线期间的数据积压行为，评估网络恢复后的数据连续性与序号断裂恢复策略。
- **实验方法**：
  1. 针对 v1 协议（不带本地持久缓存）和扩展方案（RAM 环形缓冲区暂存最近 10 条样本），分别模拟 30 秒短时断网。
  2. 记录断网前后 `sequence` 跳变。
  3. 分析服务器端接收到的序列缺口，验证去重算法能否正确捕获序列跳跃而不崩溃。
- **评价指标**：
  - 序列断裂检测准确率（识别出的真实跳号次数 / 实际制造的断网次数）。
  - 环形缓冲区有效恢复率（扩展方案下成功补传的样本比例）。

## 3. 大数据基础课程实验方案 (Big Data Experiments)

### 实验 7：宿舍环境特征描述性统计分析
- **实验目的**：掌握针对流式物联网传感器时间序列的基础统计特征提取方法，建立宿舍环境基线。
- **实验方法**：
  1. 导出连续 7 天的有效温度、湿度、归一化光照数据。
  2. 计算各维度的均值、方差、中位数、四分位距 (IQR)、偏度 (Skewness) 与峰度 (Kurtosis)。
  3. 剔除无效值与模拟测试值后，绘制箱线图 (Boxplot) 与核密度估计图 (KDE)。
- **评价指标**：
  - 统计量计算准确性（通过固定合成数据集验证算法正确性）。
  - 各指标物理含义的合理性（如昼夜温差是否符合实际季节规律）。

### 实验 8：环境时间序列分解与滑动窗口分析
- **实验目的**：将环境监测时序数据分解为长期趋势 (Trend)、季节/周期性 (Seasonality) 和残差 (Residual)，并实施滑动窗口聚合。
- **实验方法**：
  1. 按照固定时间跨度（如 15 分钟、1 小时）对原始不规则采样数据进行重采样 (Resampling)。
  2. 使用经典加法或乘法模型进行时间序列 STL 分解。
  3. 设置不同滑动窗口长度（如 $W = 5$ 点、$15$ 点），计算移动平均 (Moving Average) 和移动标准差。
- **评价指标**：
  - 重采样平滑度与方差损失比。
  - 周期性波动检测准确性（24 小时昼夜周期的显著性检验）。

### 实验 9：流数据清洗与 Schema 合规性过滤
- **实验目的**：设计健壮的数据清洗流水线，拦截协议不合规、乱序、重复及畸变传感器脏数据。
- **实验方法**：
  1. 构造包含合法数据、未知字段、超出物理量程（如温度 > 80℃）、非法时间戳格式及重复三元组的基准测试集（Test Fixture）。
  2. 通过 Python 流水线执行校验、去重和隔离。
  3. 脏数据流入独立的 `dead_letter` 队列或隔离文件。
- **评价指标**：
  - 脏数据拦截率（Recall on Dirty Samples）：$100\%$。
  - 正常样本误杀率（False Rejection Rate）：$0\%$。
  - 单条数据清洗平均耗时（单位：微秒）。

### 实验 10：传感器缺失值处理与插补策略对比
- **实验目的**：对比删除法、前向填充 (Forward Fill)、线性插值 (Linear Interpolation) 与多项式样条插值在宿舍传感器缺失场景下的表现。
- **实验方法**：
  1. 选取一段完整的 24 小时真实连续温度序列 $Y_{\text{true}}$。
  2. 人工随机屏蔽 5%、15%、30% 的数据点，模拟无线丢包造成的单点缺失与连续突变缺失（连续缺失 10 分钟）。
  3. 分别应用不同插值策略得到重构序列 $\hat{Y}$，计算重构误差。
- **评价指标**：
  - 均方根误差 (RMSE)：$\sqrt{\frac{1}{N}\sum (Y_i - \hat{Y}_i)^2}$。
  - 平均绝对误差 (MAE)：$\frac{1}{N}\sum |Y_i - \hat{Y}_i|$。
  - 各策略在突变边缘处的保真度与平滑度比较。

### 实验 11：多维度环境参数相关性分析
- **实验目的**：探究温度、湿度、光照及设备发热之间的相互影响与耦合关系。
- **实验方法**：
  1. 对齐温度、相对湿度与归一化光照的时间轴。
  2. 分别计算皮尔逊相关系数 (Pearson Correlation) 和斯皮尔曼等级相关系数 (Spearman Rank Correlation)。
  3. 绘制多变量散点图矩阵与相关性热力图 (Heatmap)。
- **评价指标**：
  - 相关系数矩阵 $R$ 的对称性与合理性（如温湿度通常呈现一定负相关，关灯开灯对光照的阶跃变化）。
  - 严禁在无因果干预实验前提下将统计相关性断言为因果关系。

### 实验 12：基于统计规则与滑动基准的异常检测
- **实验目的**：构建基于物理阈值与动态滑动统计（3-Sigma 与 IQR 原则）的确定性异常检测器，及时捕捉异常升温、通风突变或光照反常。
- **实验方法**：
  1. 设置固定安全物理范围（如室内温度正常区间 10℃ ~ 38℃）。
  2. 建立动态滑动基准：基于过去 2 小时窗口计算均值 $\mu$ 与标准差 $\sigma$，将超出 $\mu \pm 3\sigma$ 或连续 3 个采样点超出 IQR 上限的点标记为异常事件。
  3. 在测试流中注入人工合成的突变异常（如传感器接触不良产生的脉冲尖峰、暖风直吹导致的骤升），检验检测器灵敏度。
- **评价指标**：
  - 异常检出率（Detection Rate）与误报次数（False Alarms）。
  - 异常触发到事件生成的时间延迟。

### 实验 13：数据可视化与宿舍环境日报生成
- **实验目的**：实现面向用户与管理者的宿舍环境可视化图表，并自动生成脱敏的 Markdown/JSON 格式环境质量日报。
- **实验方法**：
  1. 使用 Matplotlib/Seaborn 编写自动化绘图脚本，输出日温湿度变化双 Y 轴图、光照时段分布直方图。
  2. 统计过去 24 小时舒适度指标（如处于人体舒适温湿度区间的时间占比）。
  3. 格式化输出结构化指标报告，供给 Hermes Agent 作为客观上下文。
- **评价指标**：
  - 图表要素完备性：坐标轴、法定单位、数据来源标注（严禁省略 simulated 标注）、时区标注。
  - 日报统计数值与原始数据的可复算一致性校验。

## 5. 伦理、隐私与电气安全底线

1. **同住人知情同意**：在宿舍部署真实传感节点前，必须征得全体宿舍同住同学的明确同意。严禁安装任何形式的摄像头、声音监听麦克风或推断室友作息私密信息的算法。
2. **脱敏发布原则**：提交到 Git 仓库或课程展示材料中的任何数据，必须抹去寝室楼号、房号、学号及姓名，节点 ID 仅使用匿名编号 `node01`, `node02` 等。
3. **电气与消防安全**：
   - 严禁擅自拆改宿舍强电插座或使用劣质变压器。
   - 所有 Arduino 实验节点仅允许通过合规的 5V USB 端口供电。
   - 严禁擅自连接大功率发热继电器、市电电热毯或电暖器等违章负载。
   - 宿舍无人时必须切断所有实验装置的物理电源。
