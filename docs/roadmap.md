# 三阶段路线图

本路线图按用户能获得的能力划分阶段，而不是把组件清单当作完成进度。没有排定真实日程，不虚构完成日期；团队在 issue/Projects 中填写负责人、目标日期和证据链接。

## 现状与证据口径

- 建仓起点只有 MIT LICENSE；当前协作文档描述的是设计与实施计划，不是系统运行报告。
- 已确认 UNO R4 WiFi 及部分型号未明确的传感器；传感器清单、接线和实际可测能力需要现场确认。ESP32 仅为可选项。
- WiFi、broker、HA、Hermes、真实传感器链路及多节点实验**尚未在本路线图中得到部署/验收证据**。后续代码或配置模板存在，也不代表已部署。
- 状态只能依据可追溯证据从“计划”改为“进行中”或“已验收”。模拟测试、静态检查、实物测试分别记录，不可互相替代。

## Phase 1：MVP——看到真实宿舍传感器数据

**用户目标：** 完成至少一个真实传感器的 Arduino → MQTT → HA → Hermes 演示：既能在 HA 查看最新值，也能通过 Hermes 经 HA 实时只读查询，并辨别数据过期或设备离线。

**当前状态：计划，待实物与环境验证。**

### 范围与交付

- B 核实型号、接线、电气安全和 UNO R4 WiFi 的实际可用性；实现至少一种传感器采样。
- A/B 固化节点身份、`schema_version`、单位、缺测值和 `boot_id` / `sequence` 语义。
- C 建立 WiFi/MQTT → HA 链路，交付去敏配置、实体映射和恢复步骤。
- E/C 先验证 Hermes 接入 HA 的权限与安全边界，再接入当前状态的实时只读查询；未经验证的写入能力必须禁用，不能把提示词限制当作权限隔离。接入方式依核实的上游能力实施，不虚构工具签名或接口。
- F 提供离线模拟、基本验证和查询/拒绝用例，A 组织包含 Hermes 的完整端到端检查，D 提前评审遥测镜像接口。
- 不要求额外执行器；MVP 包含真实感知和 Agent 只读查询，不包含实际控制，不把虚构的灯控当作必备能力。

### 验收门槛

1. 现场实际传感器 → UNO R4 WiFi → broker → HA → Hermes 的数据能被逐段核对；执行一次真实当前值查询，将 Agent 回答与查询时的 HA 状态、单位及更新时间对照，保存去敏日志、时间和配置版本。
2. 至少一种读数来自真实硬件，`simulated=false`；无对应传感器的字段为 `null`，不能补造数值。
3. 断线/重启之后能重新上报；分别测试缺测、陈旧和离线输入，HA 状态及 Hermes 回复均不得冒充最新有效读数。
4. 在接入真实环境前执行权限检查与操作请求拒绝测试，证明只读查询路径可用且控制未启用；若权限隔离无法验证，不得开放写入，Phase 1 仍记为待验收。
5. 仓库基础验证通过；实物及真实 Hermes 查询验收另列，不能用模拟器或静态报告代替完整链路。

**主要风险：** 校园/宿舍网络限制、传感器型号不明、供电和采样问题。允许先离线跑通协议开发，但阶段仍保持“未完成真实链路验收”。

## Phase 2：扩展——比较多节点并解释数据

**用户目标：** 扩展多传感器与多节点，保存可查询的历史数据，以可视化和可复算分析理解变化，并通过通信实验认识 Wi-Fi 信号、可靠性与恢复的限制。

**当前状态：计划；依赖 Phase 1 的稳定协议与数据链路。**

### 范围与交付

- A/C 规划多节点 topic、身份、只读订阅权限及容量边界。
- B 确认并接入额外可用传感器，覆盖至少两种实际可测环境量的扩展目标；评估可选 ESP32 或其他已确认节点。硬件不足时先用明确标记的模拟通道/节点开发，但多传感器或多实物验收继续标记待完成。
- D 只通过 broker 订阅约定的遥测镜像，持久化 `received_at` 与原始 payload，明确保留期限；交付清洗、跨重启去重、缺失处理比较、窗口统计、时间序列/相关性分析及可视化。存储采用适合小项目的轻量方案，不预设已部署数据库服务。
- C/D 验证历史持久化、重启恢复和按节点/时间范围读取；图表注明单位、缺测和真实/模拟来源。
- A/B/C/F 执行 Wi-Fi RSSI 与通信表现、断网重连及多节点负载实验；F 覆盖重复、乱序和重启，C 记录资源占用。具体方法与指标见实验文档。

### 验收门槛

1. 至少两种已确认传感器通道各提供一段真实输入和对应单位/缺测记录；逐节点核对身份，去重键包含 `(node_id, boot_id, sequence)`，重启后不误删新数据。硬件不满足时该项待验收，模拟结果单列。
2. 写入一个预先确定的观测窗口后重启采集/分析进程，按节点和时间范围读回历史；核对原始 payload、`received_at`、唯一记录数及去重后的样本数，证明历史不依赖进程内存。保留期限与删除方式有记录。
3. 用同一固定数据生成时间序列、窗口统计和相关性图表，复算抽取窗口的统计量；图表注明单位、来源、有效样本数、时间基准和缺失处理。至少比较保留缺失与一种合理处理策略，记录其影响；相关性不作因果解释。
4. 按实验文档执行至少两种可复现的 Wi-Fi 信号条件及一次断网/重连场景；记录 RSSI 分布、成功率/缺失率、观测位置、窗口与统一分母，保存输入清单和接收日志。没有可靠时钟同步不报告跨设备单向延迟。
5. 将“多节点模拟验证”和“多实物节点验证”分别列出；后者只有获得相应硬件与记录后才可宣称完成。执行多节点隔离/负载测试，报告实际规模与限制，不预写容量结论。
6. 分析账户只读，不直接或间接用 MQTT 向设备发送控制命令。

**主要风险：** 样本不足、时钟未同步、硬件数量不足。缩减统计复杂度可以接受，隐瞒来源或虚构性能不可以。

## Phase 3：Agent——得到可追溯报告并完成展示

**用户目标：** 在 Phase 1 实时只读查询基础上扩展历史查询、提醒、日报与适度角色交互，完成系统测试和可追溯展示；操作请求仅在安全路径另行验证后才可考虑开放。

**当前状态：计划；依赖可用的 HA 状态和经过验证的分析输出。**

### 范围与交付

- E/D 规划并核实历史查询与日报所需的数据接口，交付带时间范围、来源和缺测说明的报告；历史接口和自定义 Skill 在实现、测试前均标记 Planned，不编造 HTTP 路径、CLI 或工具签名。
- E/F 设计适度角色交互与提醒，角色表达不得掩盖事实、权限和不确定性；采样、异常判断、数据时效性及拒绝逻辑由确定性程序负责，不逐样本调用 LLM。
- F/C 完成全链路系统测试，覆盖当前/历史查询、日报、提醒去重与冷却、外部服务失败、断网恢复及权限；准备展示脚本、故障演示和离线备选材料。
- E/C 联合核查所有控制请求只经 HA，默认不启用；仅在另行审查并验证细粒度权限与确认机制后才讨论开放。未配置的动作必须明确拒绝。
- D 提供报告数据依据；A 汇总架构、实验边界与贡献；B 支持实物链路展示。

### 验收门槛

1. 对预先选定的历史时间窗口执行查询并生成一份日报，与持久化数据的统计量、样本数和缺测对照；报告注明时间范围、真实/模拟来源和输入依据。只有接口实际接通并完成核对后才标为通过。
2. 用固定正常/异常输入测试提醒，记录触发、重复抑制与冷却结果；角色表达不改写测量事实。无数据、数据陈旧、超出权限、外部服务不可用都有明确响应；保留系统测试矩阵及失败用例，不把计划接入说成已接入。
3. 任何执行路径可追溯到 HA，禁止 Hermes/分析脚本旁路发布设备控制消息。
4. 有可重复的展示步骤与备用材料；静态报告或离线回放明确标注，不能冒充现场 Agent 运行。
5. 六人各有实质产物、审查记录和对应验收证据。
