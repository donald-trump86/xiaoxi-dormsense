# 六人团队与协作边界

XiaoXi DormSense（交小西宿舍智能体）是西安交通大学独立六人本科课程项目，面向无线传感网络与大数据基础。A—F 是职责代号，不是成员姓名；实际成员与日期由团队自行补充。

## 共同约定

- 系统主链路：Arduino UNO R4 WiFi → WiFi/MQTT → Home Assistant（HA）→ Hermes Agent。
- 分析模块通过 broker 订阅**遥测镜像这一约定的只读接口**，不向设备发布控制命令；自动化、交互与 Agent 的控制请求只经 HA。
- 已确认硬件只有 UNO R4 WiFi 及部分型号待确认的传感器。ESP32 是可选扩展，不是 MVP 前提；继电器、执行器等不能按已到货或已接入处理。
- 下列目录是职责定位，不表示对应组件已经实现、部署或验收。实际文件名以仓库和合并后的设计为准。
- 每人必须交付可独立说明的工程产物和验证证据，不能仅以“写报告”“调用 AI”或参加会议作为实质贡献。

## 三个协作组

| 小组 | 成员 | 核心交接 |
| --- | --- | --- |
| 感知与通信组 | A、B | B 的传感器采样与重连固件通过 A 定义的 MQTT 契约进入平台 |
| 平台与数据组 | C、D | C 提供 broker、HA 和只读订阅接入条件，D 交付可复现分析 |
| Agent 与应用组 | E、F | E 通过 HA 获取状态/请求操作，F 完成交互、自动化验证与展示 |

## 每人职责、接口与验收

| 代号 | 主要职责与目录范围 | 负责的接口 | 实质交付物 | 验收条件（计划） |
| --- | --- | --- | --- | --- |
| A：架构 / MQTT 集成 | `docs/` 中架构与协议；协议相关 `tests/`、`scripts/`；协调跨模块变更 | 节点身份、topic、字段、单位、版本、`boot_id` / `sequence`；broker 与 HA 的集成边界 | 架构图、协议规范、有效/无效消息样例、协议校验与端到端集成记录 | B/C/D 对同一份契约通过评审；合法消息能被解析，非法消息被拒绝或明确标记；不产生绕过 HA 的控制路径 |
| B：固件 | `firmware/`；硬件与接线文档 | 已确认传感器 → UNO R4 WiFi 采样 → MQTT；断线重连与重启身份 | 可编译固件、实际物料/接线表、采样及重连逻辑、串口与发布日志 | 至少一种实际传感器完成带单位的真实读数；重启更换 `boot_id`；同一启动内 `sequence` 语义稳定；记录型号未知项和失败情况 |
| C：平台部署 | `deploy/`、`home-assistant/`；部署文档 | WiFi/broker 接入、MQTT → HA 实体映射、访问权限与只读分析账户 | 去敏配置示例、部署/恢复步骤、实体映射、访问权限与故障排查记录 | 按步骤可重复部署；HA 展示真实遥测并能区分不可用状态；只读账户不能发布控制；无口令入库 |
| D：分析 | `analytics/`；分析相关 `tests/`、实验文档 | 只读订阅约定的遥测镜像；清洗后的数据 → 统计/图表/报告 | 订阅与清洗程序、去重逻辑、窗口统计、异常规则或基线分析、可复现实验脚本 | 用固定输入可复算；按 `(node_id, boot_id, sequence)` 去重；明确缺失值、分母和数据来源；不向设备或控制 topic 发布消息 |
| E：Hermes 集成 | `hermes/`；Agent 接口与提示设计文档 | HA 状态读取、受控服务调用；分析结果只作解释依据 | 接入方案、状态/分析摘要报告、允许操作清单、拒绝/确认策略与测试样例 | 报告可追溯到输入和时间范围；未知值不编造；越权与不支持操作被拒绝；任何实际控制只经 HA |
| F：交互 / 自动化 / 测试 / 展示 | `presentation/`、`tests/`、`simulator/`；协作 `home-assistant/` 中自动化配置 | 用户交互 → HA；测试场景 → 设备/平台/分析/Agent 的观察结果 | 展示脚本、交互原型、自动化规则及安全检查、集成测试矩阵、离线模拟场景 | 自动化有防抖/冷却或等效约束；实物能力不足时明确使用模拟；现场演示可降级；材料清楚区分真实、模拟与计划 |

`home-assistant/`、`tests/` 等共享目录按文件分工，修改前在 issue/PR 标明负责人，不能同时覆盖他人文件。目录命名若由架构调整，应同步此表，不用空目录伪装实现进度。

## 评审与交接

1. 每项任务指定一名 owner、一名 reviewer、输入/输出、验收条件和预计阶段。
2. A/B 互审协议与固件，但协议变更还需 C/D 确认消费者兼容性。
3. C/D 互审部署与分析；D 在无实物时可先用**标注来源的模拟数据**开发，不能把它写成传感器实测。
4. E/F 互审 Agent 与交互；任何 HA 服务调用或权限变更需 C 复核，涉及设备安全时请 B 复核。
5. 每个 PR 附验证命令、结果及未完成项。仅模板或计划合并不等于实验通过。
6. 阶段验收由六人共同回看真实链路证据、缺陷清单与各自提交，不以提交次数替代工作质量。
