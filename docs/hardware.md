# 硬件清单、接线与供电指南

本文整理项目中两块核心开发板（**Arduino UNO R4 WiFi** 与 **ESP32-C3**）及传感器的型号、引脚定义、接线表与单口串联供电方法，方便对照复现或排查硬件问题。

---

## 1. 硬件物料清单（BOM）

项目硬件采购总成本为 **57.64 元**（Arduino UNO R4 WiFi 为复用已有开发板）：

| 节点归属 | 模块名称 | 接口 / 关键规格 | 用途说明 |
| --- | --- | --- | --- |
| `node01` 主控 | Arduino UNO R4 WiFi | RA4M1 + ESP32-S3 Wi-Fi 桥接，板载 12×8 LED 点阵 | 宿舍环境采集、板载点阵陪伴动效、按钮手势检测与 TLS 8883 遥测上报 |
| `node01` 温湿度 | SHT31 串口温湿度模组 | TTL UART，9600 baud，8N1，约 1 Hz 自动输出 ASCII 帧 | 实时测量室内温度（`°C`）与相对湿度（`%RH`） |
| `node01` 光照 | LM393 光敏电阻模块（4 针） | 模拟量输出 `AO`（接 `A0`），3.3V–5V | 采集环境相对明暗变化，固件端 4 次均值采样并归一化为 `0.000~1.000` |
| `node01` 交互 | 三线微动按钮开关 | 3 引脚无极性标识（接 `D2` / `D3` / `D4`） | 支持单击切换点阵画面、双击触发环境查询、长按进入语音交互 |
| `node02` 主控 | ESP32-C3 开发板 | RISC-V 单核 Wi-Fi SoC，USB Type-C | 空调红外原始脉冲采样（`learn1`）、标准库状态比对与挑战码安全回放 |
| `node02` 红外接收 | 38kHz 红外接收模块 | 解调数字输出 `OUT`，3.3V 供电 | 接收原装格力空调遥控器 280 边沿长帧及光学自检信号 |
| `node02` 红外发射 | 940nm 红外发射模块 | 数字调制输入 `DAT`，5V 供电增强发射距离 | 发送学习到的 38kHz 原始脉冲序列或光学诊断信号 |

## 2. 感知陪伴节点（`node01`：Arduino UNO R4 WiFi）接线表

固件源码位于 [firmware/arduino-uno-r4/](../firmware/arduino-uno-r4/README.md)。

| 外设模块 | 外设引脚 | UNO R4 WiFi 引脚 | 接线与电气说明 |
| --- | --- | --- | --- |
| **SHT31 串口模组** | `VCC` | `5V`（面包板正极轨） | 模组工作电压支持 5V |
| | `GND` | `GND`（面包板公共地） | 与开发板共地 |
| | `TXD` | `D0 / RX`（`Serial1`） | 模组每秒主动发送形如 `R:057.4RH 024.5C\r\n` 的 ASCII 帧 |
| | `RXD` | **悬空不接** | 仅被动接收模组周期数据，无需向传感器发送指令 |
| **LM393 光敏模块** | `VCC` | `5V` | 与 SHT31 共用面包板 5V 电源轨 |
| | `GND` | `GND` | 公共地 |
| | `AO` | `A0` | 模拟电压随光照增强而降低，固件按 `(1023 - adc) / 1023.0` 映射为相对光照 `light` |
| | `DO` | **悬空不接** | 不使用板载阈值比较器数字输出 |
| **三线按钮模块** | 三根引线 | `D2`、`D3`、`D4` | 固件 `button_scanner.h` 轮流将各脚置为 `OUTPUT LOW`、其余置为 `INPUT_PULLUP`，自动识别任意线序并在启动及持续异常 4 秒后重定基线；已识别的长按期间不重定基线，松开后发布语音结束事件 |

### UNO R4 WiFi 硬件开发注意事项

1. **串口分帧（`sht31_uart.h`）**：`Serial1` 在 9600 波特率下可能因主循环间隔将一帧末尾的 `\r\n` 切分到两次读取中。固件采用字节流状态机逐字符累积，收到完整行且校验范围（温度 `-40~125°C`、湿度 `0~100%`）通过后才更新读数。
2. **A0 ADC 与 12×8 LED 点阵的寄存器锁冲突（`main.cpp`）**：UNO R4 WiFi 的 `Arduino_LED_Matrix` 定时器中断与 `A0`（`P014`）同属 RA4M1 的 Port 0，且点阵驱动在中断返回前会通过 `R_BSP_PinAccessDisable()` 锁死 `PWPR` 写保护寄存器。因此每次读取 `analogRead(A0)` 前，固件会先消隐 Port 0/2 点阵引脚并调用 `R_BSP_PinAccessEnable()` 解除写保护，等待 200 μs 稳定后连续采样 4 次取均值，彻底消除点阵扫描对光照读数的串扰。

## 4. 双开发板单口串联供电（Daisy-Chain Power）

在桌面或宿舍长期摆放时，无需占用两个 USB 充电口，只需**一根 Type-C 数据线插入 Arduino UNO R4 WiFi**，即可同时为两块开发板供电：

```text
[USB 5V 电源 / 电脑 Type-C 口]
        │
        ▼ (Type-C 线)
[Arduino UNO R4 WiFi (node01)]
  ├─ 5V  ──────► 面包板 5V 正极轨 ──┬──► SHT31 (VCC)
  │                                ├──► LM393 (VCC)
  │                                └──► [ESP32-C3 (node02) 的 5V 引脚]
  └─ GND ──────► 面包板 GND 负极轨 ─┴──► [ESP32-C3 (node02) 的 GND 引脚]
```

- **电气安全性**：UNO R4 WiFi 在 USB 供电模式下，`5V` 引脚直通 USB `VBUS`（可提供约 500mA–1A 电流）；ESP32-C3 开发板的 `5V` 引脚经过板载 3.3V LDO 稳压芯片为芯片供电，双板合计平均电流约 150–220mA，余量充足。
- **烧录提示**：日常运行时使用单口串联供电即可；若需通过电脑 USB 单独给 ESP32-C3 重新烧录固件，建议先拔开 `5V` 借电跳线再插 C3 的 USB 线，避免两路 5V 电源并联反灌。
