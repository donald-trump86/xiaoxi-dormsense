# 交小西（Hermes）日常使用、语音交互与空调学习指南

本文介绍交小西网页端（`http://127.0.0.1:9119`）与命令行终端的日常使用方式，包括**功能精简配置、日常单会话延续、多层记忆机制、本地/云端混合语音交互**以及**对话式空调遥控器学习流程**。

---

## 1. 面向宿舍场景的精简配置

上游 Hermes 默认包含多种第三方平台与看板工具。为提升响应速度并聚焦宿舍助手场景，项目在 [hermes/config.dorm-assistant.yaml](../hermes/config.dorm-assistant.yaml) 中进行了定制精简：

- **保留的核心工具集（`platform_toolsets.cli`）**：
  - `homeassistant`：通过 `read-gateway` 读取温度、湿度、光照、按钮事件与红外事件 5 个实时实体。
  - `xiaoxi_ir_learning`：引导遥控器逐键学习，查询已存样本并按用户要求发射一次（按需通过 `tool_search` / `tool_describe` 加载）。
  - `xiaoxi_weather`：读取中国气象局天气实况；未指定城市时按本次网络出口重新定位，也可直接指定城市。
  - `memory` 与 `session_search`：维护长期偏好记忆并检索历史对话。
- **关闭的冗余组件**：
  - 禁用 `a2a-platform` 与 `spotify` 插件。
  - 关闭 `kanban` 网关通知与派发。
  - 关闭 `platforms.homeassistant` 的 WebSocket 事件订阅适配器（HA 状态查询走轻量级 REST `GET /api/states`，无需维持全量事件总线长连接）。

## 2. 网页端日常单会话自动延续与记忆机制

### 2.1 默认延续同一个日常会话
打开 `http://127.0.0.1:9119` 时，前端（由 [hermes/patches/hermes.patch](../hermes/patches/hermes.patch) 增强）会自动按当前浏览器与 Profile 读取 `localStorage` 中保存的会话 ID（键名前缀 `hermes.chat.last-session.v1`），并通过 `getSessionLatestDescendant` 接口自动续接该会话的最新分支：
- **日常连续对话**：刷新页面或次日重新打开浏览器时，默认回到同一个日常对话窗口，无需每次手动在左侧列表翻找。
- **开启新话题或查看旧记录**：点击左上角 **`New (empty)`** 会强制开启全新空白会话；点击左侧历史列表中的任意条目则会切换到对应会话并更新当前记忆指针。

### 2.2 三层记忆协同机制
在同一个日常会话中长期交流时，系统通过三层机制管理上下文：

1. **当前会话上下文与自动压缩（Context Compression）**：当前对话历史保存在 SQLite 会话库中（已设置 `sessions.auto_prune: false`，永久保留历史记录）；当单次会话 Token 接近上下文阈值时，引擎自动将早期轮次压缩为结构化摘要，使同一会话可以长期延续。
2. **跨会话持久记忆（Curated Memory）**：模型可通过 `memory` 工具将用户的长期习惯（如作息偏好、适宜温度区间、空调按键备注）写入持久记忆块（`MEMORY.md` 上限 2,200 字符，`USER.md` 上限 1,375 字符），在所有会话中自动注入。
3. **历史全文检索（`session_search`）**：当需要回忆更早之前的具体对话细节时，模型可调用 `session_search` 检索过往会话原文。
4. **实时传感数据永不依赖记忆**：工作区规则 [hermes/workspace/AGENTS.md](../hermes/workspace/AGENTS.md) 明确规定，凡涉及当前温湿度、光照或设备在线状态，必须实时调用 `ha_get_state` 工具读取最新传感器数据，绝不把上下文中的旧读数当作当前状态。

## 3. 语音识别（STT）与小西语音合成（TTS）

网页端侧边栏集成了**“小西语音交互”**控制卡片：

- **本地语音转写（STT）**：浏览器录音通过 `/api/audio/transcribe` 交由容器内本地挂载的 **Faster-Whisper（`base` 模型）** 转写，并经 `zhconv` 自动规范化为简体中文，录音数据不出宿主机。
- **云端语音合成（TTS）**：当助手回复完成（`message.complete`）或点击播报按钮时，后端通过 `/api/audio/speak` 调用 **Edge TTS** 生成 MP3 音频。网页提供 7 种中文声线，切换后会试听，并按当前选择合成。也可手动选择浏览器系统朗读。
- **中文单位朗读**：中文回复中的 `51.5%`、`22.4°C`、负数与范围会转成适合中文朗读的文本，屏幕上的原始回复保持不变。声线标签只描述音色与语言，不代表学校专属录音。
- **实体按钮语音提问**：页面打开并获得麦克风权限后，长按 UNO 按钮开始录音；松开后结束收音，转写完成即自动发送。也可点击网页按钮开始或停止。

## 4. 对话式空调遥控器逐键学习

当 ESP32-C3（`node02`）与 `ir-learning` 服务在线时，可直接在对话中完成原装遥控器波形录制：

1. **启动学习**：对小西说 **“初始化空调”**（调用 `xiaoxi_ac_initialize`），系统自动创建学习档案并开启 45 秒的 `baseline`（基准帧）采样窗口。
2. **录制基准帧**：将原装格力遥控器对准 ESP32-C3 的红外接收头（避开空调主机方向）按一次开关键，待小西播报已捕获 280 边沿基准帧及当前温度/模式状态。
3. **逐键防呆录制**：按小西提示依次录制 **开关（`power`）→ 模式（`mode`）→ 升温（`temp_up`）→ 降温（`temp_down`）→ 风速（`fan`）→ 上下扫风（`swingv`）**。
   - 每按完一个键，向小西说“录好了，下一个”。
   - 系统会自动比对前后两帧的 14 个标准字段；若不小心按错了键，小西会指出实际发生变化的字段并引导重按该键。
   - 若遇到遥控器上没有的扩展功能键（如左右扫风、睡眠、干燥等），直接说“没有这个键，跳过”即可。

## 5. 使用已存样本控制空调

录制过目标状态后，可以说“打开空调”或明确提出“制热 28 度”。小西先用 `xiaoxi_ac_list_commands` 查询档案，按完整的开关、模式、温度和风速状态选择样本，再调用 `xiaoxi_ac_send` 发射一次。默认使用当前档案，也能查询旧档案；没有匹配样本时会说明缺少哪个设置。

用户已经明确要求的操作不需重复确认。`power` 标签既可能对应开机也可能对应关机，不能当作通用切换键；学习接收窗口开启时也不能发送。发射超时或结果不明时不会自动重试，避免重复控制。

小西会区分“节点确认信号已发出”和“空调实际响应”。目前没有空调侧执行反馈，收到节点回执或本机回波后仍不能断言空调已经开关或达到设定温度。

## 6. 天气实况与动态城市

可以问“现在外面温湿度多少”“比较宿舍内外温湿度”，或直接指定“北京现在温度多少”。工具从中国气象局读取当前观测；不提供未来预报。

未指定城市时，每次查询都会通过国内城市定位服务重新识别网络出口所在地，不保存固定默认城市或回退到上一次位置。回答会说明实际查到的城市。网络出口可能受 VPN 或代理影响，发现城市不对时可直接指定城市。

定位只用于城市匹配，不把 IP 地址和精确坐标写入结果或配置；定位失败、城市有歧义或观测过期时会明确说明，避免把旧数据当作当前天气。详细接口与测试见[天气插件说明](../hermes/plugins/xiaoxi_weather/README.md)。
