# XiaoXi DormSense 展示指南

交小西宿舍智能体是西安交通大学独立六人本科课程项目，覆盖无线传感网络与大数据基础。本目录用于组织报告、演示脚本和后续展示材料；当前这份指南是**计划**，不是已有幻灯片、部署或实测成果的证明。

## 讲清楚的主线

1. **问题与范围**：如何在尊重同住人员隐私的前提下感知宿舍环境、理解变化并提供有边界的交互。
2. **系统链路**：UNO R4 WiFi → WiFi/MQTT → Home Assistant → Hermes Agent。
3. **分析旁路**：分析程序只订阅 broker 提供的约定遥测镜像，负责清洗、去重、统计与解释；它不是设备控制通道。
4. **控制边界**：所有控制只经 HA。没有确认执行器时，可以只演示感知、报告或测试实体，不虚构灯控等实物能力。
5. **课程价值**：说明无线传感节点身份、通信与恢复，以及流式数据清洗、窗口统计、数据质量和分析限制，而非只展示聊天界面。

## 现场演示脚本（执行前逐项确认）

### 1. 开场声明

说明当天演示属于“真实现场 / 模拟 / 回放 / 混合”中的哪一种，以及实际启动的组件。混合演示要逐段说明来源，不能只在末尾用一句“部分模拟”含混带过。

### 2. 真实端到端链路

- 核实实际传感器型号、接线、电源、网络与 broker/HA 可用性。
- 展示一个实际节点的真实读数及 HA 对应实体，核对单位与缺测；不要宣称所有环境量都有传感器支持。
- 安全地观察一次环境变化；如展示断网/重启，预先确认不会影响共享网络或其他住户。
- 观察恢复和新 `boot_id`，说明序号可以在新启动中重置。

如果无法完成，明确说“当前真实链路未通过现场验证”，再切换降级方案。

### 3. 分析与解释

展示同一数据窗口的原始样例、去重与统计结果，指出分析账户只读。解释 `(node_id, boot_id, sequence)` 为什么必要；给出缺失率时现场指出分母与宽限期。没有可靠参考仪器或标签时，不展示无依据的精度/准确率。

### 4. Agent 与权限

仅在 Hermes 确已接入时演示真实报告；否则展示明确标注的“报告模板/计划接口”。至少展示一个无数据或超出能力的请求，以及拒绝/确认策略。实际控制必须可追溯到 HA；没有执行器时不声称发生物理动作。

### 5. 结尾

总结真实完成项、已知限制、下一步及六人贡献。展示失败也是有效工程证据，不要临时替换成伪造日志。

## 离线备选方案

在仓库根目录运行：

```bash
python3 simulator/mqtt_node.py --count 3
```

默认只打印三条离线模拟消息，不连接 broker，不代表 MQTT/HA/Hermes 已部署。可用它讲解协议字段、`simulated=true`、启动身份与序号。基础验证使用：

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 scripts/check_repository.py
```

Python 3.11+ 和依赖准备参见 [开发流程](../docs/development.md)。基础验证只说明对应代码/仓库检查结果，不替代现场硬件验收。

若使用预录屏、截图或日志，须标注采集日期、代码版本、真实/模拟来源及剪辑说明；材料必须真实存在且事先去敏。尚未准备材料时保持“待准备”，不要在报告中宣称已有备用录像。
